# WordDeck commercial content provenance gate

This directory contains the canonical machine-readable seam for the WordDeck commercial-content rights policy defined by `WD-MASS120-089-CONTENT-RIGHTS-PROVENANCE` and independently audited by `WD-MASS120-098-AUDIT-CONTENT-RIGHTS`.

`content_provenance_manifest.json` is intentionally empty at introduction time. An empty manifest does **not** clear existing Oxford-backed lexical/audio data, Tatoeba content, AI-assisted course assets, private books, or any other content family. It means no asset has yet been registered here as `CLEARED_PRODUCTION` under this contract.

## Commercial release rule

A public/commercial package must be gated from its **actual packaged bytes**, not from a hand-written list. The package contains one `CONTENT_ASSET_INDEX.json` with schema version `1.0`, one or more explicit `content_roots`, and a one-to-one mapping of stable provenance `asset_id` to relative packaged path. `tools/build_release_content_inventory.py` walks every file under those roots, rejects unindexed files, missing indexed files, duplicate IDs/paths, symlinks and path traversal, and hashes the exact shipped bytes. Its inventory is then validated with:

`tools/validate_content_provenance_strict.py --manifest ... --inventory ... --require-inventory [--notices ...]`

The only authorized producer for this commercial gate is `.github/workflows/worddeck-package-recovery.yml`, and the only accepted release artifact identity is `worddeck-windows-release-candidate`. `.github/workflows/worddeck-commercial-release-provenance.yml` requires both the producer workflow-run ID and the exact 40-hex source SHA. `tools/validate_commercial_package_source.py` fails closed unless that run is the authorized workflow path, ran successfully on `worddeck-bootstrap`, has the exact requested source SHA, and exposes exactly one unexpired artifact with the stable authorized name. A successful unrelated WordDeck workflow cannot satisfy this contract, and callers cannot substitute a free-form artifact name.

The package producer materializes `CONTENT_ASSET_INDEX.json` only after build, source/published self-tests, package-cleanliness checks and real Windows UIA close/reopen/replacement recovery acceptance. The index binds the exact source SHA, producer-workflow path and stable artifact name. The commercial consumer checks those bindings again before constructing inventory from actual package bytes.

The current engineering producer is deliberately **fail closed** for commercial publication: it writes `commercial_release_eligible=false` plus an explicit HOLD marker because no production content family is currently asserted as commercially cleared by this seam. The commercial consumer requires `commercial_release_eligible=true`, so today's engineering package cannot accidentally become a commercial-rights PASS merely because packaging succeeded. A future rights-cleared package may set that flag true only as part of an independently reviewed source change that supplies the exact production asset index and provenance evidence. Do not hand-edit a workflow input or package after the producer run to bypass this hold.

The strict entrypoint reuses `validate_content_provenance.py` for common manifest/release invariants and adds MASS089 fail-closed policy. Every manifest asset has explicit `version` and `production_owner`. A `CLEARED_PRODUCTION` asset additionally requires a concrete rightsholder/licensor, license or agreement identity, territory and explicit end-user-use permission. Missing permissions default to denial; exact SHA-256 identity and `CLEARED_PRODUCTION` are mandatory; release channel, expiry, dependency graph, review/hash binding and required notices must resolve.

Dependency eligibility is **transitive**. A shipped asset cannot hide an expired, review-failed, blocked, private, channel-incompatible or otherwise non-releasable upstream dependency behind a direct dependency whose status happens to be `CLEARED_PRODUCTION`. The strict gate walks the full dependency chain cycle-safely and applies commercial/channel/expiry/review/notice restrictions to every upstream asset.

Origin-specific policy is also fail closed. In particular, a generic Oxford terms/license snapshot is not commercial permission: an Oxford-backed asset cannot be production-cleared without explicit OUP permission/license contract or scoped legal opinion. Tatoeba text requires source-export, license and attribution evidence; Tatoeba audio also requires its own audio-license/attribution evidence and an explicit source-text license. AI-assisted assets require a non-empty material-input list whose stable IDs resolve in the same manifest and are explicit dependencies; duplicate/self/dangling inputs are rejected, and the exact AI output hash must bind the output asset. TTS voice-rights/output-terms evidence IDs and native-audio speaker-release evidence IDs must resolve to compatible evidence records rather than merely being non-empty strings. Production native audio also requires recording ownership, master hash, a manifest-resolved source-text dependency and explicit voice-cloning/AI-training declarations.

The engineering candidate remains an engineering evidence package and is not converted into a commercial-rights PASS by this change. In particular, this gate does not invent an Oxford license, Tatoeba/audio clearance, contributor assignment, voice right, legal opinion, production rights approval, or physical NVDA proof. Those must be supplied from real evidence and actual package construction before a commercial artifact can pass.

The `review.reviewed_content_hash_sha256` field binds the rights/originality/source review to the exact bytes/text under review. Changing `content_hash_sha256` without re-review therefore fails deterministically.
