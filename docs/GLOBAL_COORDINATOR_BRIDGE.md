# Global Coordinator Bridge

Accessible Chess participates in the owner's cross-project autonomous development control plane.

## Purpose

Workers, Codex Cloud and Work must not rely on stale prompt text as the current project plan. Before substantive work, reconstruct the newest Accessible Chess state and read current coordination surfaces. The coordinator updates shared priorities; Oleksii should not need to manually rewrite worker prompts after each external development run.

## Coordination hierarchy

1. Global coordinator master: cross-project priorities for Nika Core, 12-6 AI, Accessible Chess and future projects.
2. Project-local plan: `coordination/AUTONOMOUS_ROUTING.md` — current Accessible Chess priority, completed work, do-not-repeat items, active temporary ownership and next unowned packages.
3. Worker execution: each run takes only current useful work and leaves durable evidence.

## Current activation

Accessible Chess was explicitly reactivated by Oleksii on 2026-09-07. The active operating mode is five productive hourly workers using one shared live routing plan. This replaces the previous low-frequency/paused posture while the owner keeps this project active.

All five workers remain developers. Worker 5 carries integration and audit responsibility only when an audit is due; otherwise it performs implementation/integration work. A full project audit is normally due about every six hours, immediately after a major state change, or as failover when the normal audit is stale for about eight hours.

## Audit and anti-duplication rule

Before substantive work every worker must compare the newest repository/PR/CI/report state with its inherited assignment, then classify the target as KEEP, CHANGE, STOP_STALE, COLLISION or PROMOTE. Active work uses temporary reservations/ownership markers and a do-not-repeat list. A live Codex/Work package or current convergence branch is not to be independently reimplemented by another worker.
