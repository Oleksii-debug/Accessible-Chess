# Перекодування PGN: перевірка та користування

## Клавіатурний сценарій у Windows

Це інструкція для нового кандидата вихідного коду; вона не означає, що зміна
вже є у раніше завантаженому Windows ZIP. Фізичний тест NVDA ще потрібний.

1. Натисніть Alt. Стрілками перейдіть до меню «Експорт», натисніть Enter.
   Стрілкою вниз знайдіть «Перекодувати PGN у UTF-8 (нова копія)», Enter.
2. Tab до кнопки «Вибрати джерело», Enter. У стандартному вікні відкриття
   перейдіть Tab до поля «Ім’я файлу», введіть повний шлях до свого PGN,
   натисніть Enter. Джерело повинно бути до 8 МіБ.
3. Фокус переходить до «Кодування джерела». Залиште «Автоматично» або
   відкрийте список через Alt+стрілка вниз, виберіть кодування стрілками
   та підтвердьте Enter. Для Windows-1252, CP866, KOI8-R/KOI8-U й Latin-1
   потрібен явний вибір. UTF-16 має містити BOM.
4. Tab до «Перевірити й переглянути», Enter. Після завершення фокус
   переходить у текстове поле «Звіт і перегляд тексту». Ctrl+Home — початок
   звіту; стрілки — читання; Ctrl+A, Ctrl+C — скопіювати звіт.
5. Перевірте, чи правильно читаються імена й коментарі. Зміна кодування
   скидає попередній перегляд; після неї виконайте перевірку знову.
6. Tab до «Зберегти новий UTF-8 PGN», Enter. У стандартному вікні збереження
   задайте нове ім’я `.pgn`. Наявний файл та оригінал не перезаписуються.
   Після запису фокус повертається до звіту з текстовим результатом.
7. Під час роботи Escape або кнопка «Скасувати операцію» просить скасування.
   Якщо публікація вже завершилась, результат залишається успішним і створена
   копія зберігається. У неробочому стані Escape закриває вікно.

Фоновий виконавець не читає UI-контролі. Оновлення тексту й фокуса виконує
подія завершення на UI-потоці. Скасування перевіряється під час читання,
між обмеженими фазами канонічного парсингу та між записами партій;
окрему фазу парсингу не можна миттєво перервати.

## Автоматично перевірено

- 95 локальних тестів сервісу, життєвого циклу вікна, меню та чинних
  PGN/Library контрактів: PASS. Окремий реальний WinForms STA smoke на Linux
  пропущений; для нього додано Windows CI, результат не вважається відомим
  до завершення точного запуску.
- Синтаксис/imports нових модулів, основний CLI, `acs.selftest`, production
  composition diagnostic: PASS.
- Скасування під час серіалізації: немає опублікованого часткового файла
  або залишеного `.tmp`.
- Зміна джерела після перегляду, невідоме/неправильне кодування, суперечлива
  BOM, пошкоджений PGN, завелике джерело, оригінал як призначення та вже
  наявний файл: запис відхиляється.
- Українські шляхи з пробілами; nested RAV, коментарі, NAG, clock-коментар,
  SetUp/FEN та чорні починають із нестандартної позиції: збереження перевірено.
- Книга Markdown з одним явно позначеним PGN на блок → канонічні GameTree;
  імпорт у ACSDB й пошук українського імені: PASS.

## Реальний корпус

`PGN_CONVERSION_REAL_CORPUS_20261005.json` містить машинний звіт без приватних
шляхів або корпусу. Джерело — офіційний Lichess standard rated 2013-01,
CC0; перевірено повний SHA-256 архіву. Взято перші 1000 повних партій
до заголовка Event партії 1001, 730269 байтів; SHA-256 вибірки:
`78d54a3eb536be06b6bb26f871edafebdf037c4c90af7fc1ccd4f4071048f6a5`.

UTF-8, BOM UTF-16 LE, BOM UTF-16 BE та явний Windows-1251 дали однаковий
UTF-8 результат:
`a610ef67872295321ac649fb1bb07ceedd0b298f7f605d27ba6ecaaf4f3433c3`.
Кожен транспорт перевіряє всі 1000 record_digest, відкриття в PGN workspace
та незмінність джерела. Потім: Library import → close/reopen → keyset search
усіх записів → повний filtered PGN export → порівняння всіх record_digest,
SQLite `integrity_check=ok`.

Ця вибірка має 61169 ходів, 344 коментарі, 76 NAG; RAV і нестандартних
стартів немає. Вони перевірені окремими синтетичними тестами; це не
реальна анотована комерційна книга й не доказ підтримки ChessBase.
Оракул використовує канонічну D06 identity, а не незалежний сторонній
PGN-парсер. Можливості перевірки не перебільшуються.

Повторення: підготуйте цю hash-pinned вибірку й виконайте
`python scripts/qualify_pgn_conversion_corpus.py SOURCE.pgn --expect-source-sha256 78d54a3eb536be06b6bb26f871edafebdf037c4c90af7fc1ccd4f4071048f6a5 --expected-games 1000`.
Скрипт працює офлайн, перевіряє digest до роботи й не змінює SOURCE.

## Межі приймання

Загальний локальний прогін на початковому кандидатові: 4737 тестів,
125 failures, 66 errors, 12 skips. Це НЕ GREEN усього проєкту.
Окремий прогін незміненої бази потрібний для точного віднесення цих
помилок; його результат фіксується в PR/наступному checkpoint.

Не перевірено фізично: Windows/NVDA, реальні натискання клавіш користувачем,
фінальний скомпільований ZIP із новим пунктом меню, реальна придбана
анотована книга. Не підтверджено: попит або ціна.

HUMAN_TESTED=NO; NVDA_VERIFIED=NO; FINAL_WINDOWS_ZIP=NO.
Наступний крок: завершити точний Windows native CI і включити цей
нащадок у Product-інтеграцію зі збереженням актуальних Books/PGN власників;
потім фізичний NVDA сценарій на новому пакеті. Наступна продуктова робота
за дослідженням — повний сценарій читання реальної PGN-книги й
публікації власної доступної збірки з явним обліком втрат.
