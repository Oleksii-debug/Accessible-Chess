ПОВНА КОНЦЕПЦІЯ ACCESSIBLE CHESS
КАНОНІЧНЕ БАЧЕННЯ ОЛЕКСІЯ ДЬОРДЯЯ
НЕ ЗВУЖУВАТИ ПРОЄКТ ДО ПОТОЧНОГО STAGE 1


ВАЖЛИВО


Цей текст описує не лише те, що потрібно реалізувати зараз, а повне довгострокове бачення Accessible Chess.


Поточний Windows/NVDA Stage 1 — лише фундамент.


Не можна робити висновок, що функція не потрібна лише тому, що вона не входить у поточний release.


Особливо не можна втрачати тренерський/Classroom-напрям.


ГОЛОВНА ІДЕЯ ПРОЄКТУ


Accessible Chess повинна стати повноцінним шаховим середовищем, у якому незряча людина може:


грати;
аналізувати;
читати шахові книги;
працювати з позиціями;
працювати з партіями;
працювати з PGN;
працювати з великими базами;
використовувати Stockfish;
навчатися;
викладати;
вести учнів;
проводити індивідуальні та групові заняття;
готувати й видавати завдання;
працювати з матеріалами ChessBase;
працювати через Windows, Web і надалі мобільні платформи.


Ключовий принцип:


Незрячий користувач не повинен отримувати "спрощену версію шахів".


Він повинен мати функціональність, максимально близьку до тієї, яку має зрячий шахіст, аналітик або тренер, але керувати нею клавіатурою та NVDA.


==================================================
1. ДВІ СТОРОНИ ОДНІЄЇ ПРОГРАМИ
==================================================


Accessible Chess повинна одночасно мати:


A. НЕВІЗУАЛЬНИЙ ІНТЕРФЕЙС ДЛЯ НЕЗРЯЧОГО КОРИСТУВАЧА.


B. ПОВНОЦІННЕ ВІЗУАЛЬНЕ ПРЕДСТАВЛЕННЯ ДЛЯ ЗРЯЧОГО УЧНЯ, ГЛЯДАЧА АБО СУПЕРНИКА.


Це принципово важливо для тренерської роботи.


Олексій як незрячий тренер працює клавіатурою і NVDA.


Дитина бачить нормальну красиву шахову дошку, фігури, покажчики, підсвічування, стрілки та інші пояснення.


Тренер не повинен фізично користуватися мишкою, щоб отримати результат, який зрячий тренер зазвичай створює мишкою.

==================================================

Незрячий користувач переміщується по ній стрілками.


Наприклад:


Right:
e4 → f4.


Left:
e4 → d4.


Up:
e4 → e5.


Down:
e4 → e3.


На краях дошки немає wrap.


Користувач повинен чути:


координату;
фігуру;
колір;
за необхідності додаткову інформацію про поле.


Потрібен швидкий спосіб отримати:


що стоїть на полі;
що атакує поле;
хто атакує поле;
які поля контролює вибрана фігура;
повну позицію;
матеріал;
останній хід;
статус шаху/мату тощо.

15. ГОЛОВНА ТРЕНЕРСЬКА ІДЕЯ
НЕЗРЯЧИЙ ТРЕНЕР → ЗРЯЧА ДИТИНА
==================================================


Це одна з принципових майбутніх функцій Accessible Chess.


Мета:


Олексій як незрячий тренер повинен проводити заняття для зрячих дітей на тому самому професійному рівні візуальної демонстрації, який має зрячий тренер.

==================================================
16. KEYBOARD VISUAL POINTER
==================================================


Олексій конкретно запропонував такий UX.


Окремою гарячою клавішею викликається спеціальне поле/редактор керування демонстраційною дошкою.


Це НЕ поле вводу шахових ходів.


Це поле керування візуальним покажчиком.


Тренер вводить:


f3


Після завершення координати:


візуальний курсор / pointer / simulated mouse pointer автоматично переходить на поле f3.


Якщо на f3 стоїть фігура — для дитини візуально очевидно, що тренер зараз показує саме на цю фігуру.


Поле введення автоматично очищається.


Тренеру НЕ треба натискати Backspace.


Він відразу вводить:


c7


Pointer миттєво переходить на c7.


Потім:


a1


Pointer переходить на a1.


Таким чином незрячий тренер "водить мишкою" по дошці, фактично вводячи координати клавіатурою.


Він повинен робити це дуже швидко під час живого пояснення.


Не змушувати його:


шукати поле стрілками;
переміщувати реальну mouse pointer фізично;
виконувати зайві підтвердження;
очищати поле вручну.


UX повинен бути оптимізований під швидку усну лекцію.

17. POINTER НЕ ОБОВ'ЯЗКОВО МАЄ БУТИ СИСТЕМНОЮ МИШКОЮ
==================================================

Наприклад:

рамка навколо поля;
анімований marker;
видимий кружок;
стрілка;

Головний контракт:


тренер вводить координату клавіатурою;
учень миттєво бачить, на яке поле/фігуру тренер вказує.


==================================================
18. ВІЗУАЛЬНЕ ПІДСВІЧУВАННЯ
==================================================


Тренер повинен мати keyboard-first команди для візуального підсвічування.


Приклади:


ввести e4 → позначити e4;
ввести e4 + відповідну hotkey → виділити поле;
вибрати фігуру → підсвітити всі легальні поля, куди вона може піти.


Наприклад:


тренер вибирає коня;
натискає гарячу клавішу;
для зрячої дитини зеленим кольором показуються всі клітинки, куди цей кінь може легально піти.


Це повинно працювати на основі реальної chess legality, а не pseudo moves.


Потенційно потрібні окремі режими підсвічування:


легальні ходи;
атаковані поля;
захищені поля;
цільове поле;
кілька вибраних полів.


Колір повинен бути configurable.


Зелений може бути стандартом для legal moves.

хід;

атаку;
маневр;
пішаковий прорив;
план;
маршрут фігури.


Тренер повинен мати змогу створити кілька стрілок і очистити їх однією командою.

==================================================
22. ІСТОРІЯ POINTER ДИТИНИ
==================================================


На сторінці/в інтерфейсі тренера потрібна динамічна доступна область.


У ній зберігається послідовність полів, на які дитина показувала.


Наприклад:


f3
e5
d4
c6


Не треба обов'язково показувати timestamp для кожної дії.


Головне — послідовність.


Так тренер через NVDA може зрозуміти:


"дитина спочатку показала f3, потім e5".


Це дуже важливо під час запитань типу:


"Покажи, де стоїть кінь."


"Покажи слабке поле."


"Куди ти хочеш поставити ферзя?"

==================================================

75. НЕ ПЛУТАТИ POINTER З MOVE
==================================================

e4


у Teacher Pointer Editor —


це НЕ шаховий хід.

Програма ніколи не повинна гадати неправильно, що означав текст.

Pointer не є ходом.


Hover учня не є ходом.

==================================================
77. ПРИКЛАД РЕАЛЬНОГО УРОКУ
==================================================


Тренер відкриває Classroom.


Обирає групу "Початківці".


Відкриває lesson.


На дошці початкова позиція.


Тренер натискає hotkey Teacher Pointer.


Пише:


e2


Діти бачать pointer на білому пішаку e2.


Тренер пояснює:


"Це білий пішак."


Пише:


e4


Pointer переходить на e4.


Тренер показує:


"Пішак може піти сюди."


Далі тренер вибирає коня g1.


Натискає команду Show legal moves.


Учні бачать зеленими:


f3
h3


Тренер вимикає highlight.


Питає:


"Покажіть, куди може піти кінь."


Передає board input одному учневі.


Учень клацає f3.


NVDA тренера повідомляє:


"Учень Іван вибрав f3."


Тренер бачить це невізуально й продовжує урок.


Оце і є основна ідея:


незрячий тренер керує повноцінним візуальним уроком без необхідності бачити екран.


==================================================
78. ПРИКЛАД СИЛЬНІШОГО УРОКУ
==================================================


Тренер відкриває PGN партії.


Переходить до критичної позиції.


Створює pointer на d5.


Малює стрілку:


c3 → d5.


Підсвічує e5.


Питає:


"Яке тут слабке поле?"


Учень вибирає e5.


Тренер чує відповідь.


Потім учень робить варіант.


Тренер аналізує його через GameTree.


Stockfish доступний тренеру, але прихований від учня.


==================================================
79. ПРИКЛАД ДОМАШНЬОЇ РОБОТИ
==================================================


Тренер вибирає п'ять позицій.


Створює assignment:


"Знайти найкращий хід."


Учень отримує завдання.


Розв'язує.


Наступного разу тренер бачить результати.


Може відкрити неправильну відповідь прямо на дошці й пояснити її.


==================================================
80. КІНЦЕВА МЕТА
==================================================


Accessible Chess не повинна залишитися "шаховою програмою для сліпих".


Кінцева мета значно ширша:


універсальна професійна шахова платформа, accessibility-first за архітектурою, але придатна одночасно для незрячих і зрячих користувачів.


Незрячий шахіст повинен мати професійний інструмент для гри й аналізу.


Незрячий читач — для книг і баз.


Незрячий тренер — для повноцінного навчання зрячих і незрячих дітей.


Зрячий учень не повинен відчувати, що отримує "спрощену дошку для незрячого тренера".


Він повинен бачити сучасний нормальний chess-learning interface.


Тренер повинен отримувати той самий зміст через keyboard/NVDA.
