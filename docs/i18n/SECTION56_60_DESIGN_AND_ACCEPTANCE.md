ГРАМАТИКА/СИНТАКСИС: перевірити КОЖНЕ речення; рід, число, відмінок, узгодження, дієвідміну, артиклі, прийменники, класифікатори, порядок слів, вид/час, модальність, заперечення, пасив, форми звертання і специфічні для конкретної мови категорії; plural/select/відмінювані динамічні вставки імітувати реальними числами/іменами.
4. ОРФОГРАФІЯ/ПУНКТУАЦІЯ/ТИПОГРАФІКА: чинний правопис, діакритики та вибрана система письма, великі літери, апостроф, лапки, пробіли, перенос, знаки пунктуації, Unicode/grapheme/RTL, змішані латинські координати шахів, формати дат і чисел.
5. СТИЛЬ/РЕЄСТР: кожне речення має бути професійним, грамотно і природно написаним згідно з нормами конкретної мови, зі сталою формою звертання та ввічливістю; витримати тон меню, кнопок, навчання, помилок, підтверджень та NVDA-описів без штучного AI-стилю, жаргону, невдалого канцеляризму чи дослівної англійської конструкції.
6. ШАХОВИЙ КОНТЕКСТ: нормативно перевірити назви фігур, ходів, шаха/мату/пату, рокірування, перетворення, дебютів, ендшпілю, тактики, оцінок, часу, пояснень і навчальних повідомлень; зберегти canonical GameTree/Board/FEN/PGN/SAN без зміни істини шахової позиції. 7. ДОСТУПНІСТЬ ЗНАЧЕННЯ: кожна aria-name/description, live announcement, клавіатурна підказка й голосове повідомлення передає ту саму дію без двозначності, з правильною граматикою динамічних параметрів, в усіх Windows/Web/функціональних розділах.
8. НЕЗАЛЕЖНА ПРОФЕСІЙНА QA: компетентний носій літературного стандарту / фаховий перекладач і, для термінів шахів, фаховий рецензент мають незалежно перевірити КОЖЕН контекстний translatable key, не лише випадкову вибірку. Зберігати трасування source → target → context → grammar/idiom/chess decisions, source key, version, evidence, reviewer identity/qualification, QA date, issue/fix disposition і signed approval.
